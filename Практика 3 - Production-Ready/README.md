## 4. Создание Docker-образа

На первом этапе был создан образ приложения на основе Python 3.11. Зависимости устанавливались отдельно от исходного кода, после чего копировался файл `main.py`.

Для исключения ненужных файлов из контекста сборки был создан `.dockerignore`. В него добавлены правила исключения кэша Python, виртуального окружения, Git и файлов с настройками окружения.

## 5. Многоэтапная сборка

Для уменьшения размера итогового образа использовалась многоэтапная сборка Docker.

На этапе `builder` устанавливаются инструменты, необходимые для сборки зависимостей, включая `gcc`, `musl-dev`, `python3-dev` и `libffi-dev`.

На следующем этапе используется отдельный образ `python:3.11-alpine`. В него копируются установленные зависимости, исходный код приложения и необходимые для проверки состояния инструменты.

Компиляторы из этапа сборки в итоговый образ не копируются.

Размер итогового образа `secure-api:v3` составил 126 МБ по данным Docker.

## 6. Безопасность контейнера

Для повышения безопасности были выполнены следующие настройки:

* создан пользователь `appuser` и группа `appgroup`;
* приложение запускается от пользователя `appuser`, а не от `root`;
* используется параметр `USER appuser`;
* основная файловая система контейнера запускается в режиме только для чтения;
* отключены дополнительные Linux capabilities с помощью `--cap-drop ALL`;
* включён параметр `no-new-privileges`.

Для запуска приложения используется exec-форма `CMD`, которая запускает Uvicorn напрямую.

## 7. Логирование

Путь к файлу логов задаётся переменной окружения `LOG_FILE`:

```text
/var/log/app/app_logs.txt
```

Каталог `/var/log/app` объявлен как Docker volume. Это позволяет приложению записывать логи даже при запуске контейнера с параметром `--read-only`.

Работа логирования была проверена командой:

```bash
docker exec secure-api cat /var/log/app/app_logs.txt
```

В результате была получена запись:

```text
Generated hash for a user
```

## 8. Проверка состояния приложения

В Dockerfile настроен `HEALTHCHECK`, который проверяет доступность endpoint `/health` каждые 30 секунд.

Проверка API выполнялась командой:

```bash
curl http://localhost:8080/health
```

Ответ приложения:

```json
{"status":"ok"}
```

Статус контейнера проверялся командой:

```bash
docker inspect --format='{{json .State.Health.Status}}' secure-api
```

Результат:

```text
"healthy"
```

## 9. Проверка генерации хеша

Для проверки работы `bcrypt` был выполнен запрос:

```bash
curl "http://localhost:8080/hash?password=test123"
```

Приложение вернуло JSON с хешем пароля. Это подтвердило работу endpoint `/hash`.

## 10. Запуск защищённого контейнера

Для проверки ограничений безопасности использовалась команда:

```bash
docker run -d \
  --name secure-api \
  -p 8080:8080 \
  --read-only \
  --cap-drop ALL \
  --security-opt no-new-privileges \
  secure-api:v3
```

После запуска контейнер успешно прошёл проверку состояния и получил статус `healthy`.
